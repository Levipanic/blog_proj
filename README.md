# StereoDamage Blog

Личный микроблог / дневник. Никаких аккаунтов читателей, никакой рекламы,
никакой аналитики. Статическая раздача — MPA на Express + SQLite + ванильный
HTML/CSS/JS. Вдохновлён старым твиттером и атмосферой личных сайтов 2000-х.

## Возможности

- Лента постов с поддержкой текста, заголовков, разделителей, медиа (изображения,
  GIF, видео, аудио) и спойлеров
- Комментарии с именем (опционально), треды, антиспам
- Лайки постов и комментариев
- Админ-панель по ключу (однопользовательская, без регистраций)
- Читательские настройки в `localStorage`: тема, режим списка/сетки, прогресс
  чтения, громкость

## Быстрый старт

### Требования

- **Node.js >= 20.0.0** (проверьте версию: `node -v`)

### Установка

```sh
git clone <repo-url> blog
cd blog
npm install
cp .env.example .env
```

Отредактируйте `.env` — как минимум смените `ADMIN_SECRET` на что-то надёжное.

### Запуск

```sh
npm run dev    # разработка (с авторестартом при изменениях)
# или
npm start      # продакшен
```

При первом запуске автоматически создадутся `data/blog.db` (SQLite) и директория
`uploads/`.

Сайт будет доступен на `http://localhost:3000`. Админ-панель — `/admin`.

### Продакшен

На продакшене обязательно:

1. Установите `NODE_ENV=production`
2. Поменяйте `ADMIN_SECRET` на случайную строку (не дефолтную)
3. Если сервер за reverse proxy — включите `TRUST_PROXY=true`
4. Настройте HTTPS (через reverse proxy или напрямую)

## PM2 (фоновый запуск)

Проект работает под [pm2](https://pm2.keymetrics.io/) — процессы живут в фоне
и автоматически перезапускаются при падении или перезагрузке сервера.

```sh
# Установка pm2 (один раз)
npm install -g pm2

# Запуск приложения
pm2 start backend/server.js --name blog

# Остановка
pm2 stop blog

# Перезапуск
pm2 restart blog

# Просмотр логов
pm2 logs blog

# Сохранить список процессов (чтобы они жили после перезагрузки)
pm2 save
pm2 startup   # выполнить команду, которую выведет pm2
```

## Бэкап и восстановление

### Что бэкапировать

Полный снапшот проекта включает три компонента:

| Компонент | Путь | Содержимое |
|---|---|---|
| База данных | `data/blog.db` | Посты, комментарии, лайки, сессии, антиспам |
| Медиафайлы | `uploads/` | Загруженные изображения, GIF, видео, аудио |
| Конфигурация | `.env` | Переменные окружения (секреты, настройки) |

Остальное (код, зависимости) восстанавливается из git.

### Создание бэкапа

Проект целиком умещается в архив с одного сервера, скачивается и хранится
отдельно.

```sh
# На сервере: останавливать сервер необязательно, но желательно,
# чтобы SQLite точно был в консистентном состоянии.
pm2 stop blog

# Архивируем всю папку проекта во /tmp
cd /home/user
tar -czf /tmp/blog-snapshot-$(date +%F).tar.gz blog/

# Убедитесь, что архив нормально создался
ls -lh /tmp/blog-snapshot-$(date +%F).tar.gz

# Запускаем сервер обратно
pm2 start blog
```

После этого скачайте архив с сервера себе:

```sh
# У себя на машине
scp user@server:/tmp/blog-snapshot-2026-07-11.tar.gz /safe/storage/location/
```

> **Важно:** `.gitignore` исключает `*.db` в `data/` и всё в `uploads/` (кроме
> `.gitkeep`). База и медиа **не попадают** в git — архив всей папки проекта
> содержит и их, и код, и .env, и node_modules, что гарантирует полную
> воспроизводимость.

### Восстановление (на новой машине или после аварии)

```sh
# 1. Скопируйте архив на новую машину (если его там ещё нет)
scp /safe/storage/location/blog-snapshot-2026-07-11.tar.gz user@new-server:/tmp/

# 2. На новой машине — распакуйте
cd /home/user
tar -xzf /tmp/blog-snapshot-2026-07-11.tar.gz

# 3. Убедитесь, что стоит правильная версия Node.js
node -v   # должно быть >= 20.0.0

# 4. Установите зависимости (если архивировали без node_modules)
cd blog
npm install

# 5. Запустите
pm2 start backend/server.js --name blog

# Сайт снова работает на http://localhost:3000 или через reverse proxy.
```

### Автоматизация (cron)

Пример — еженедельный архив с удалением старых (старше 90 дней):

```
0 3 * * 0  cd /home/user && \
  tar -czf /tmp/blog-snapshot-$(date +\%F).tar.gz blog/ && \
  find /tmp -name "blog-snapshot-*.tar.gz" -mtime +90 -delete
```

Не забывайте периодически скачивать архивы с сервера в надёжное хранилище.

Храните бэкапы в месте, отдельном от сервера.

## Безопасность

- `/admin` и все admin API требуют валидной сессии (ключ в `ADMIN_SECRET`)
- Комментарии проходят многоуровневую антиспам-проверку (скоринговая система, без
  жёстких правил)
- Подозрительные комментарии уходят в `pending`, не удаляются
- Rate limit на всех публичных эндпоинтах
- Поля ввода экранируются, HTML не рендерится
- Загружаемые файлы проверяются по размеру, расширению и MIME-типу
- Raw IP не отображаются в админке — только хеши
